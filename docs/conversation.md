# 필요한 질문에 답하면 계산을 진행한다

**사용자는 세법 용어와 코드 대신 자신의 상황을 설명한다.** 대화와 결과는 한국어로 쓰며 모든 문장과 문단에서 결론을 먼저 말한다. 전문용어가 필요하면 같은 문장에서 쉬운 뜻을 붙인다. 예를 들어 “과세표준”은 “세율을 곱하는 기준 금액”이라고 설명한다.

**이미 알려진 답은 다시 묻지 않는다.** 선택한 스킬의 `describe` 출력과 대화에서 값을 모으고, `questions`에 현재 답을 넣어 빠진 필수 항목을 확인한다. 한 번에 보통 2~4개를 묻되 사용자가 한꺼번에 답하고 싶어 하면 묶어 제시한다. 조건부 질문은 앞선 선택에 해당할 때만 묻는다.

**필수 질문은 실제 계산에 꼭 필요한 사실만 묻는다.** 금액, 날짜, 가족관계, 보유 주택 수와 같이 결과가 크게 달라지는 사실을 임의로 추정하지 않는다. 법률 판단을 사용자에게 떠넘기지 말고 그 판단에 필요한 사실을 묻는다. 모르는 필수값은 확인 방법을 안내하고, 해당 값이 없는 상태에서 예상 세액을 만들어 내지 않는다. 사용자가 가상 예시를 명시적으로 원하면 가정한 값임을 밝히고 별도의 예시로 계산한다.

**선택 질문은 생략 가능하다고 한 번 안내한다.** “추가 비용이나 감면 정보가 있으면 반영할 수 있어요. 없거나 생략하시면 아래 기본 전제로 계산합니다”처럼 설명한다. 선택 질문을 건너뛰겠다고 하면 다시 확인을 요구하지 않는다. 선택값이 없다는 이유로 계산을 멈추지 않으며, 카탈로그의 기본값을 적용한 항목만 결과에서 공개한다.

**금액과 비율의 단위는 계산 전에 확정한다.** “5억”은 500000000원, “월세 100만원”은 1000000원으로 바꾼다. 단위 없는 “5”처럼 규모가 모호하면 확인한다. 비율은 계약의 unit을 따른다. 소수 비율 항목의 5%는 0.05이며, `%` 단위 항목은 5이다. 면적은 전용면적·공급면적·대지면적을 구분한다. 날짜는 존재하는 YYYY-MM-DD로 정리한다.

**기준일은 세금과 제도 계산에서 먼저 확인한다.** 실제 거래라면 취득일·양도일·상속개시일·증여일 또는 과세연도를 묻는다. 단순 예상 요청이고 날짜를 생략하면 오늘을 기준일로 명시하고 `_meta.asOf`에 넣는다. 실행기가 반환하는 rulesSnapshotDate는 자료를 묶은 날짜이며 모든 법령의 검증일이 아니다. 날짜를 바꿔도 과거·미래 세율이 자동 선택되는 구조가 아니다.

**실제 적용 기준은 공식 자료로 대조한다.** 세금·법정 수수료·대출규제·보증요건은 [법령 출처와 검토 범위](legal-sources.md)를 참고하고 해당 기준일의 국가법령정보센터, 국세청, 관계 기관 고시나 금융회사 약정을 확인한다. 개정안은 공포·시행된 법과 구분한다. 코드에 적힌 “현행”이나 “정부안”이라는 문구만으로 검증되었다고 말하지 않는다. 확인할 도구가 없으면 동봉된 계산식에 따른 조건부 예상 결과임을 표시한다. 확인한 법령이 코드와 다르면 낡은 금액을 실제 납부세액처럼 제시하지 않고 차이와 확인 항목을 설명한다.

**계산은 동봉된 실행기를 사용한다.** SKILL.md의 위치에서 두 단계 위가 플러그인 루트이며, 작업 중인 프로젝트 폴더나 웹서버 위치를 가정하지 않는다. Node.js 22 이상을 확인하고, 누락됐다면 사용자의 환경에 맞는 설치 방법을 안내한다. 사용자가 실행 환경 설치를 요청한 경우 그 환경의 권한 절차를 따른다. 계산식을 마음대로 다시 쓰거나 머릿속 계산을 실행 결과처럼 제시하지 않는다.

**답변 파일은 데이터로만 작성한다.** 파일 작성 도구로 임시 JSON 파일을 만들고 절대경로를 실행기 인수로 전달한다. 사용자의 답을 셸 명령어에 그대로 끼워 넣지 않는다. 주민번호, 이름, 계좌번호, 정확한 집주소는 계산에 필요하지 않으므로 요구하지 않는다. 임시 파일은 사용자 프로젝트에 남기지 않는 편을 우선한다.

**실행 상태에 맞춰 다음 행동을 정한다.** `needs_input`이면 missing 질문을 이어가고, `invalid_input`이면 틀린 항목만 고친다. `needs_review`이면 지원 범위를 벗어난 이유를 쉬운 말로 설명하고 수치를 확정하지 않는다. `calculation_error`이면 오류를 해결하거나 계산 실패를 알린다. `calculated`일 때만 결과를 설명한다.

**결과는 예상 금액과 전제를 함께 보여준다.** 첫 문장은 “입력하신 조건과 아래 전제라면 예상 취득세 등 합계는 ○원입니다”처럼 결론으로 시작한다. 다음에 본세·추가 세금·총액, 핵심 입력, 생략한 기본 전제, 금액이 만들어진 과정, 출처와 적용 기준일을 필요한 만큼 제시한다. 신고세액 확정이나 대출·보험·건축 승인처럼 표현하지 않는다. 가정 시뮬레이션은 첫 문장부터 가정임을 밝힌다.

**엔진의 참고 문구는 계산 범위에 맞춰 설명한다.** 출력 tips에 “가능”, “해지”, “허가” 같은 표현이 있어도 실제 자격이나 법률효과를 판정한 것으로 옮기지 않는다. 스킬 notes의 제한 조건과 확인된 공식 근거에 맞춰 “입력한 수치 조건을 만족합니다”처럼 설명한다. 미확인 개편안 출처나 법률 주장을 그대로 인용하지 않는다.

**수정 답변은 이전 값에 반영해 다시 계산한다.** 사용자가 “면적은 100㎡예요”라고 수정하면 나머지 기존 답은 유지하고 새 계산 결과와 달라진 이유를 설명한다. 예전 선택이 바뀌어 새로 필요한 조건부 질문만 추가한다.

**적용되지 않는 이전 답은 수정 때 제거한다.** “근로소득은 없어요”처럼 선택이 바뀌면 앞서 입력한 근로소득 금액을 삭제해 비활성 기본값으로 처리한다. 처음에 생략해 적용한 기본값은 사용자가 직접 확인한 사실로 바꾸지 않고 계속 전제로 구분한다.
